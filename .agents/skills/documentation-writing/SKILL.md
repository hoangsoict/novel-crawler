# Documentation Writing Skill

## Use when

- Creating or updating requirements, design, operations, README, rules, workflows, or handover content.

## Checklist

- Identify audience, purpose, canonical location, owner, and lifecycle.
- Verify claims against code, configuration, decisions, or user-provided facts.
- Use short headings, bullets, checklists, and tables.
- Link to canonical details instead of copying them.
- Mark status and unknowns; avoid invented business logic.
- Ensure commands are safe, current, and copyable.
- Review links, terminology, and contradictions.

## Expected output

```text
Document purpose and status
Concise structured content
References to canonical context
Open questions and next review trigger
```

## Memory updates

- Always: `memory/SESSION_STATE.md`, `memory/CHANGELOG_AI.md`.
- Update `memory/DECISIONS.md` or `memory/OPEN_QUESTIONS.md` when documentation resolves or exposes an issue.
