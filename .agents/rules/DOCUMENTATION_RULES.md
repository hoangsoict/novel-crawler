# Documentation Rules

- Keep one canonical source for each fact; link instead of duplicating.
- Use concise English for AI context. Product docs may use Vietnamese if that is the team language.
- Prefer headings, bullets, checklists, and tables over long prose.
- Mark unknowns explicitly and track them in `memory/OPEN_QUESTIONS.md`.
- Separate approved decisions from proposals.
- Include dates, owners, status, assumptions, and acceptance criteria where relevant.
- Update docs in the same task as the behavior they describe.
- Never claim a command, test, or review was completed unless it was actually performed.
