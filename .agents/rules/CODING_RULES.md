# Coding Rules

- Read approved URD/design and confirm acceptance criteria before coding.
- Make the smallest coherent change; avoid unrelated refactors.
- Follow established project structure and style; do not introduce a new pattern silently.
- Validate external input and handle timeouts, retries, rate limits, and partial failures explicitly.
- Add or update tests for behavior changes.
- Keep source-specific crawling logic isolated behind clear interfaces once architecture is approved.
- Do not suppress errors or weaken tests to obtain a passing result.
- Run relevant format, lint, type, test, and build checks; report exact results.
- Update documentation and AI memory after the task.
